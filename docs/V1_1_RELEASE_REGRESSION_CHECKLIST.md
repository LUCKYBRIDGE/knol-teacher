# 놀티쳐 v1.1.0 Release Regression Checklist

이 문서는 v1.1.0 Stable Release 승격 전에 Windows 10/11 x64 실제 실행 환경에서 수행해야 하는 수동 회귀 점검의 기준이다.
자동 CI 통과만으로 Stable Release로 승격하지 않는다.

## 판정 원칙

- 각 항목은 `PASS / FAIL / N/A`로 기록한다.
- `FAIL`이 하나라도 있으면 Stable Release 승격을 중단한다.
- 데이터 저장 관련 항목은 기존 사용자 데이터가 있는 상태와 신규 설치 상태를 모두 확인한다.
- 듀얼 모니터 관련 항목은 가능하면 실제 2개 디스플레이 환경에서 확인한다.
- 학생 이름 입력 없이 학생 번호만 사용하는 Local-Only 흐름이 정상 동작해야 한다.

## 1. 시작 및 기본 실행

- [ ] `놀티쳐.exe` 단일 파일만으로 실행된다.
- [ ] 첫 실행과 재실행 모두 스플래시가 비정상적으로 오래 멈추지 않는다.
- [ ] 메인 창이 표시된 뒤 기본 조작이 즉시 가능하다.
- [ ] 이미 실행 중인 상태에서 다시 실행하면 새 인스턴스를 만들지 않고 기존 창을 앞으로 가져온다.
- [ ] 종료 후 다시 실행했을 때 마지막 저장 상태 때문에 앱이 시작 불가 상태가 되지 않는다.

## 2. 기본 시간표 / 주간 시간표

- [ ] 기본 시간표를 편집하고 저장한 뒤 재시작해도 유지된다.
- [ ] 주간 시간표를 수정해도 기본 시간표 원본은 변경되지 않는다.
- [ ] `주간 시간표를 기본 시간표로 초기화`가 정확히 동작한다.
- [ ] 같은 요일의 두 교시 맞바꾸기가 정확히 동작한다.
- [ ] 서로 다른 요일의 두 교시 맞바꾸기가 정확히 동작한다.
- [ ] 주간 시간표 창을 닫은 뒤 메인 화면의 시간표 표시가 즉시 최신 상태로 갱신된다.
- [ ] 빈 교시, 긴 과목명, 연속 수정 후에도 저장 데이터가 깨지지 않는다.

## 3. 판서 및 수학 교구

- [ ] 일반 판서에서 마우스/펜 입력이 정상이다.
- [ ] 멀티터치 환경에서 두 개 이상의 터치 입력이 비정상적으로 합쳐지거나 끊기지 않는다.
- [ ] 투명 화면 판서가 다른 화면 요소 위에서 정상 동작한다.
- [ ] ESC 키로 닫도록 설계된 판서/도구 창이 일관되게 닫힌다.
- [ ] 자, 삼각자, 각도기의 이동/회전 핸들이 정상 동작한다.
- [ ] 수학 교구 반투명 표시가 판서 내용을 과도하게 가리지 않는다.

## 4. 놀보드

- [ ] 놀보드가 캔버스 기반 배치/이동 흐름에서 정상 동작한다.
- [ ] 타이머, 뽑기, 주사위, QR, 메모, 점수, 체크리스트 등 핵심 위젯을 추가할 수 있다.
- [ ] 위젯을 여러 개 동시에 배치해도 포커스/드래그/닫기 동작이 충돌하지 않는다.
- [ ] 놀보드를 닫았다 다시 열었을 때 비정상적인 중복 창이나 잔상이 남지 않는다.

## 5. 학생 뽑기 및 학생 표시

- [ ] 학생 이름 없이 번호만 등록한 상태에서 뽑기 기능을 사용할 수 있다.
- [ ] 이름을 선택적으로 등록한 경우 번호와 이름 표시가 올바르게 연결된다.
- [ ] 학생 표시 창을 열고 닫는 과정에서 메인 창 상태가 꼬이지 않는다.
- [ ] 저장된 학생 데이터가 외부 서버/AI 전송을 요구하지 않고 Local-Only로 동작한다.

## 6. 듀얼 모니터 / 팝업 창

- [ ] 보조 화면에 학생 표시/수업용 팝업 창을 정상적으로 띄울 수 있다.
- [ ] 모니터가 1개뿐인 환경에서도 기능 호출이 예외 없이 안전하게 처리된다.
- [ ] 보조 모니터 연결/해제 후 다시 창을 열 때 화면 밖 좌표에 고립되지 않는다.
- [ ] 창 닫기 후 재호출하면 중복 인스턴스나 죽은 참조 때문에 실패하지 않는다.

## 7. 지연 로딩된 도구 창

다음 도구는 메인 창 시작 시 미리 생성되지 않고 필요할 때 생성되므로 첫 호출과 재호출을 모두 확인한다.

- [ ] 타이머
- [ ] 학생 뽑기
- [ ] 화면 판서
- [ ] 실물화상기/Visualizer
- [ ] 플로팅 툴바
- [ ] 자리 바꾸기
- [ ] 소리판
- [ ] 전자서명
- [ ] 수업 허브

각 도구에 대해 다음을 확인한다.

- [ ] 첫 실행이 실패하지 않는다.
- [ ] 닫은 뒤 다시 열 수 있다.
- [ ] 다른 도구를 연속 실행해도 앱 전체가 멈추지 않는다.

## 8. 저장 / 복구

- [ ] 설정 변경 후 강제 종료에 가까운 상황에서도 다음 실행 시 JSON/설정 파일이 읽기 불가 상태가 되지 않는다.
- [ ] 기존 저장 데이터가 있는 상태에서 v1.1.0 실행 시 데이터가 유지된다.
- [ ] 손상 파일 복구/backup 경로가 있는 저장소는 실제로 복구 가능한 상태를 유지한다.

## 9. 패키지 및 버전

CI에서 자동 검증하지만 Stable Release 직전 최종 산출물에서도 다시 확인한다.

- [ ] 배포 폴더에는 `놀티쳐.exe` 한 파일만 존재한다.
- [ ] 실행 파일의 FileVersion이 현재 `KnolTeacherVersion`과 일치한다.
- [ ] SHA-256 해시를 기록한다.
- [ ] GitHub Stable Release에는 `KnolTeacher.exe` 한 asset만 게시한다.
- [ ] 업데이트 서비스가 해당 Release의 HTTPS URL, 파일 크기, SHA-256, embedded FileVersion 검증을 통과한다.

## 10. Stable Release 승격 조건

다음 조건을 모두 만족해야 v1.1.0 Stable Release로 승격한다.

1. PR CI 성공
2. 이 체크리스트의 필수 항목 PASS
3. 치명적/높음 수준 회귀 버그 0건
4. 실제 배포용 실행 파일의 버전과 SHA-256 확인
5. 교사가 체감하는 변화만 담은 사용자용 릴리스 노트 확정
6. `release/release-version.txt`를 실제 승격 버전으로 변경
7. GitHub Release에 `KnolTeacher.exe` 단일 asset 게시
